# Agent usage sources

Reviewed 2026-11-24 against vendor documentation and published protocol types.

| Source | What Herdr can show | How to read it |
| --- | --- | --- |
| Claude Code | Subscription quota for the rolling 5-hour and weekly windows, with reset times. Behind a supported gateway, the gateway spend limit is a separate meter. Session context, cost estimate, and model are separate fields. | Claude Code sends JSON to the configured `statusLine` command on stdin. The documented subscription windows are `rate_limits.five_hour` and `rate_limits.seven_day`, each with `used_percentage` and Unix-second `resets_at`. They appear after the first API response for supported plans and can be absent independently. Claude Code drops expired windows. These meters cover shared subscription usage. Some plans have an additional Fable limit, which the status line payload omits. [Anthropic status line documentation](https://code.claude.com/docs/en/statusline#rate-limit-usage), [Claude usage limits](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work) |
| Codex | ChatGPT account quota by metered bucket, potentially with a model-specific bucket. Each bucket can have primary and secondary windows. | Run `codex app-server` over stdio, send `initialize` and acknowledge with `initialized`, then call `account/rateLimits/read`. Prefer `rateLimitsByLimitId` when populated and fall back to `rateLimits`. Use `usedPercent`, derive the window label from `windowDurationMins` when supplied, and read optional Unix-second `resetsAt`. Use the bucket label or ID when available. Account token summaries and thread token events describe activity. [App Server guide](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt), [window schema](https://raw.githubusercontent.com/openai/codex/main/codex-rs/app-server-protocol/schema/typescript/v2/RateLimitWindow.ts), [bucket schema](https://raw.githubusercontent.com/openai/codex/main/codex-rs/app-server-protocol/schema/typescript/v2/RateLimitSnapshot.ts) |
| Gemini CLI | The interactive `/stats model` is documented to show per-model session tokens and applicable quota. Authentication determines which quota applies. | Headless JSON and streaming JSON document token and latency metrics for a run. A background account quota read remains undocumented in the Gemini CLI headless reference. The upstream TUI handles remaining amount, limit, and an optional reset time internally. For Gemini Developer API keys, Google documents project-level, model-specific rate limits in AI Studio. [Gemini CLI quotas](https://geminicli.com/docs/resources/quota-and-pricing/#check-usage-and-limits), [headless output](https://geminicli.com/docs/cli/headless/#output-formats), [TUI source](https://github.com/google-gemini/gemini-cli/blob/main/packages/cli/src/ui/AppContainer.tsx), [Gemini API limits](https://aistudio.google.com/docs/rate-limits) |
| OpenCode | Session or project activity by model, including tokens and cost. OpenCode Go also provides provider quota for the applicable subscription or team member across paid models. | Recent CLI versions document `opencode stats --json`, including `--models`, `--cost`, and project or time filters. OpenCode exposes session usage separately through its GUI plugin API. Go provides an authenticated `GET /inference/go/v1/usage` with `rolling`, `weekly`, and `monthly` meters, each with used percent and an ISO 8601 reset time. Other providers need a usage source for their own quota. [OpenCode stats](https://opencode.ai/docs/cli/commands/#stats), [GUI usage data](https://opencode.ai/docs/build/plugins/gui/#usage-data), [OpenCode Go usage](https://opencode.ai/docs/console/go/#usage) |
| GitHub Copilot | Monthly account entitlement by quota type, including counts, percentage remaining, and a reset date when supplied. | The Copilot SDK's `account.getQuota` returns `quotaSnapshots` for the authenticated user. Bucket keys come from the response and entitlement can be unlimited. The SDK also exposes session activity separately. [Copilot SDK usage and billing](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing#account-quota-and-premium-interactions) |

## Display implications

- Label a meter with the provider, the reported bucket or plan where useful, the time window, and a consistent direction such as `Claude · 5h 34% used · resets 18:40`. Keep model-specific buckets distinct from shared account or workspace buckets. If several panes share an account, they can show the same quota without adding the percentages together.
- Include reset information when the source supplies a timestamp. If a window disappears or a snapshot goes stale, show that state separately from a measured `0% used`.
- Label activity with its own scope and units, for example `OpenCode · session · 84k tokens` or `Gemini · session · 21k tokens`. A context meter describes the current conversation. A quota meter measures consumption against a provider-reported allowance.
- OpenCode Go and Copilot have documented paths for future quota adapters. Gemini headless output can support an activity adapter using runs the user already makes.
